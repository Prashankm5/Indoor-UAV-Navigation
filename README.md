# Indoor UAV Navigation

**A MATLAB-Based Framework for Robot Navigation, Motion Planning, Feedback Control, and LiDAR Sensing**

**Research Areas:** Autonomous Robotics · Robot Navigation · Motion Planning · Path Planning · Robot Perception · LiDAR-Based Systems · Feedback Control · Aerial Robotics · Ground and Surface Robotics

---

## Project Overview

This project presents a MATLAB-based simulation framework for autonomous navigation of a UAV in known two-dimensional indoor environments.

The framework integrates global path planning, feedback control, simplified UAV dynamics, collision checking, and simulated LiDAR sensing within a modular simulation architecture.

The navigation system uses an occupancy-grid representation of the environment and the A* search algorithm to generate a collision-avoiding global path. A PD controller tracks the generated waypoints, while a planar translational dynamics model updates the UAV position and velocity.

A simulated 360° LiDAR sensor generates range measurements and point-cloud data through geometric ray casting.

The project evaluates the navigation framework across five different indoor environment configurations.

**Current implementation:** Known-map, two-dimensional UAV navigation simulation.

## Key Features

- Two-dimensional indoor environment modelling.
- Occupancy-grid generation and obstacle inflation.
- Eight-connected A* global path planning.
- Diagonal corner-cutting prevention.
- PD-based waypoint tracking.
- Simplified planar UAV dynamics.
- Acceleration and velocity constraints.
- 360° LiDAR ray-casting simulation.
- LiDAR point-cloud generation.
- Discrete and continuous trajectory collision validation.
- Five experimental environment configurations.
- Automated result generation and performance reporting.

```text
UAV Position and Orientation
             |
             v
      360° LiDAR Simulation
             |
             v
          Ray Casting
             |
             v
      Range Measurements
             |
```

**Important:** LiDAR is currently a passive sensing and visualization subsystem. Its measurements do not construct the occupancy grid or influence the A* planner and PD controller. Navigation relies on the predefined environment map.

## Mathematical Methodology

### 1. Environment Representation

The simulated indoor environment is:

$$
W \times H = 10\,\text{m} \times 10\,\text{m}
$$

The occupancy-grid resolution is:

$$
\Delta x = \Delta y = 0.1\,\text{m}
$$

Therefore, the grid contains:

$$
N_x \times N_y = 100 \times 100
$$

Occupancy values:

| Value | Description |
|---|---|
| 0 | Free space |
| 1 | Occupied space |

Obstacles are represented using circular geometry.

### 2. Obstacle Inflation

Obstacles are inflated to account for the UAV radius and an additional safety margin.

$$
R_{\mathrm{inflated}} = R_{\mathrm{UAV}} + R_{\mathrm{safety}}
$$

Using:

$$
R_{\mathrm{UAV}} = 0.25\,\text{m}
$$

$$
d_{\mathrm{safety}} = 0.15\,\text{m}
$$

The resulting inflation radius is:

$$
R_{\mathrm{inflated}} = 0.40\,\text{m}
$$

### 3. A* Path Planning

A* finds a path between the start and goal positions using:

$$
f(n) = g(n) + h(n)
$$

where:

- $g(n)$: Accumulated cost from the start.
- $h(n)$: Estimated cost to the goal(Huristic).
- $f(n)$: Total estimated cost.

The planner uses an eight-connected neighbourhood:

- Cardinal movement cost: $1$.
- Diagonal movement cost: $\sqrt{2}$.
- Euclidean-distance heuristic.
- Diagonal corner-cutting prevention.

### 4. UAV Dynamics

The UAV is represented by a simplified planar translational model:

$$
\dot{\mathbf{p}} = \mathbf{v}
$$

$$
\dot{\mathbf{v}} = \mathbf{a}
$$

The numerical integration uses semi-implicit Euler:

$$
\mathbf{v}_{k+1} = \mathbf{v}_k + \mathbf{a}_k \Delta t
$$

$$
\mathbf{p}_{k+1} = \mathbf{p}_k + \mathbf{v}_{k+1}\Delta t
$$

Acceleration and velocity are limited by predefined maximum values.

This model does not represent complete six-degree-of-freedom multirotor dynamics.

### 5. PD Waypoint Tracking

The position error is:

$$
\mathbf{e} = \mathbf{p}_{\mathrm{target}} - \mathbf{p}
$$

The acceleration command is:

$$
\mathbf{a}_{\mathrm{cmd}} = K_p\mathbf{e} - K_d\mathbf{v}
$$

The controller function supports an integral term, but the current configuration uses $K_i=0$. The implemented controller therefore operates as a PD controller.

### 6. LiDAR Ray Casting

The simulated LiDAR configuration is:

| Parameter | Value |
|---|---:|
| Field of view | 360° |
| Angular resolution | 1° |
| Number of beams | 360 |
| Maximum range | 5 m |
| Initial orientation | 0° |

Each ray is tested against the four room boundaries and circular obstacles. The nearest valid non-negative intersection is selected.

The current sensor model is idealized and does not include measurement noise, missed detections, or uncertainty.

## Experimental Evaluation

Five scenarios are used to examine navigation performance under different environment configurations.

| Scenario | Description |
|---|---|
| E1 | Reference environment |
| E2 | Relocated obstacles |
| E3 | Narrow passage |
| E4 | Cluttered environment |
| E5 | Different start and goal |

### Navigation Performance

| Metric | E1 | E2 | E3 | E4 | E5 |
|---|---:|---:|---:|---:|---:|
| A* expanded nodes | 1943 | 2170 | 70 | 1468 | 2365 |
| Global path length (m) | 10.720 | 10.661 | 7.029 | 10.661 | 11.087 |
| Trajectory length (m) | 10.429 | 10.410 | 6.982 | 10.360 | 10.745 |
| Final position error (m) | 0.02749 | 0.02749 | 0.02932 | 0.02749 | 0.03221 |
| Final speed (m/s) | 0.04793 | 0.04793 | 0.04856 | 0.04793 | 0.04971 |
| Simulation time (s) | 86.05 | 85.55 | 63.45 | 85.35 | 90.15 |
| Goal reached | Yes | Yes | Yes | Yes | Yes |
| Collision | No | No | No | No | No |

### Result Interpretation

Across the five recorded scenarios:

- A* generated a path in every tested environment.
- The UAV reached the specified goal in all five recorded runs.
- No collision was reported.
- Final position error ranged from approximately 0.0275 m to 0.0322 m.
- The narrow-passage scenario required fewer expanded A* nodes than the other tested scenarios.

These results demonstrate successful operation for the selected test cases. They are not a statistical performance guarantee or evidence of successful navigation in arbitrary environments.

## Installation and Execution

### Requirements

- MATLAB.
- Project source files.
- A MATLAB installation supporting the functions used in the project.

ROS 2, Gazebo, PX4, and ArduPilot are not required for the current MATLAB simulation.

### Clone the Repository

```bash
git clone https://github.com/Prashankm5/Indoor-UAV-Navigation.git
```

Open the project directory in MATLAB.

### Run the Simulation

The main entry point is:

```matlab
main
```

The scenarios can be selected in `main.m`:

```matlab
selected_scenarios = [1, 3, 5];
```

To run all five scenarios:

```matlab
selected_scenarios = 1:5;
```

Simulation outputs are saved automatically under a timestamped folder in `Results/`.

## Current Scope and Limitations

The current project is a known-map, two-dimensional UAV navigation simulation.

Its limitations include:

- The occupancy grid is generated from predefined environment information.
- LiDAR measurements do not update the planning map.
- SLAM has not been implemented.
- Position is assumed to be available; no localization algorithm is implemented.
- The UAV uses simplified planar translational dynamics rather than a complete six-degree-of-freedom model.
- Obstacles are static.
- The LiDAR sensor is idealized.
- Evaluation is based on five predefined scenarios rather than extensive statistical testing.

## Broader Research Relevance

Although the current implementation focuses on UAV navigation, several underlying methods have broader applications in robotics.

Occupancy-grid representation, graph-based path planning, collision checking, waypoint tracking, and sensor-based perception are also relevant to ground and autonomous surface robotic systems.

Applying these methods to other platforms would require suitable modifications to the vehicle dynamics, sensing configuration, environmental representation, and control architecture.

The current repository does not claim to implement ground or surface robotic navigation.
